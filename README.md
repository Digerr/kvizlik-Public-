# Квизлик 5.0

Мобильная викторина на русском: 12 тем, короткие раунды, выживание и асинхронные дуэли с друзьями. Работает в браузере, Telegram Mini App и VK Mini App. В обычном браузере регистрация не требуется.

## Что изменилось

- Новый интерфейс «бумага / графит»: четыре раздела, поиск тем, читаемые ответы, пауза и постоянный выход из раунда.
- Один расчёт наград для игрового состояния и экрана результата. Повторный вызов завершения или открытия сундука не начисляет награду снова.
- Таймер завершает вопрос на нуле; выбранный ответ блокируется сразу.
- Выживание продолжается без внешнего генератора вопросов. После ошибки доступно одно продолжение за 100 игровых монет.
- Дуэль сохраняет ровно 10 вопросов в исходном порядке. Повреждённая ссылка отклоняется, а не подменяется случайными вопросами. Счёт сравнивается по правильным ответам.
- Исправлены 125 повторяющихся идентификаторов вопросов. Подбор предпочитает непройденные вопросы.
- Ежедневную цепочку можно получить только после игры и только один раз за день.
- Облако больше не сливает расходуемые монеты через `max`. Ошибка чтения не разрешает перезаписать существующий облачный профиль.
- Сборка проверяет TypeScript. Старый API, который подтверждал любую Telegram-подпись, заменён проверкой HMAC и срока действия.
- Из навигации убраны незавершённые кланы, друзья, события, турниры и генерация AI. Старые модули остаются в коде для последующей отдельной разработки.

## Локальный запуск

Node.js 22+ и npm.

```sh
npm ci
npm run dev
```

Открыть http://localhost:3000.

```sh
npm test
npm run typecheck
npm run lint
npm run build
npm start
```

`build` создаёт standalone-сборку с публичными файлами. В Vercel используется обычный Next.js deployment. Локальный Prisma-клиент оставлен для совместимости со старой структурой проекта; основное сохранение прогресса использует Zustand/localStorage и Supabase.

## Конфигурация

| Переменная                           | Назначение                                                                 |
| ------------------------------------ | -------------------------------------------------------------------------- |
| `NEXT_PUBLIC_SUPABASE_URL`           | URL Supabase; без неё используется прежний проект                          |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY`      | Публичный anon-ключ Supabase                                               |
| `TELEGRAM_BOT_TOKEN` или `BOT_TOKEN` | Только сервер: проверка Telegram initData                                  |
| `NEXT_PUBLIC_SITE_URL`               | Адрес приложения для ссылок вне браузерного контекста                      |
| `ENABLE_AI_QUESTIONS`                | По умолчанию генератор выключен; `true` включает экспериментальный API ZAI |

Бот-токен и service-role ключи нельзя помещать в переменные с префиксом `NEXT_PUBLIC_`.

Дополнительные поля ежедневной цепочки описаны в `supabase/migrations/20261006_daily_chain.sql`. SQL нужно применить в существующем Supabase-проекте; он не выполняется при сборке. При старой схеме сохраняются основные поля профиля, цепочка остаётся локальной.

## Проверки и границы

Автоматические тесты проверяют банк и подбор вопросов, таймер, блокировку ответа, начисления, сундуки, продолжение выживания, дуэли, ежедневные награды, смену аккаунта и Telegram-подпись. Браузерный прогон проверяет полный раунд и разбор, паузу, перезагрузку, темы, категории, экран 320 px, оба участника дуэли и выживание.

Прогресс в браузере хранится на этом устройстве. Одновременная игра на нескольких устройствах использует последний сохранённый снимок; это не серверная система объединения транзакций.

Дуэли по ссылке и очки вычисляются на клиенте. Это дружеская игра, не защищённый денежный турнир. Проверка HMAC в `/api` не заменяет полноценную авторизацию прямых обращений к Supabase. Перед использованием рейтинга для призов нужен серверный подсчёт и проверенные RLS-политики. Права существующего Supabase-проекта и реальный запуск внутри Telegram/VK не проверены в этой среде.

Структура банка проверена автоматически; это не полная редакторская проверка всех фактов. Некоторые старые вопросы могут требовать уточнения формулировок. При изменении вопроса сохраняйте уникальный стабильный `id`.
